# 1. Context

**Problem:**
Tenant Administrators (business owners) require secure APIs to search, list, assign roles/branches, and lock/unlock accounts of employees (Staff and Sales agents) within their tenant. To support this safely, booking operations must validate permissions at the branch level, restricting Sales agents from physical vehicle handovers/returns and limiting branch-scoped users to assigned branches.

**Affected Modules:**
- `auth-module` (Backend): Implements account CRUD, role converters, lock toggles, and multi-tenant scoping.
- `booking-module` (Backend): Enforces ABAC security rules (restricting Sales agents from handover/returns and scoping branches) and converts booking statuses to numeric values.

**Non-Goals:**
- Frontend Angular UI implementation (deferred to a subsequent phase).
- Global Super Admin UI/API consoles.
- Self-registration workflows for Staff/Sale.

# 4. Contracts

## Interface: `AccountManagementService`

```text
AccountManagementService.listAccounts(tenantId: UUID): List<AccountResponseDTO>
  - pre: tenantId is not null
  - post: returns all accounts linked to the tenant; role is mapped to 1, 2, or 3
  - throws: TenantNotFoundException if tenant does not exist

AccountManagementService.swapRoleAndBranches(tenantId: UUID, targetUserId: UUID, request: RoleSwapRequestDTO): void
  - pre: tenantId, targetUserId, request are not null; request.role is in (2, 3)
  - post: user_tenants.role updated; user_branches re-linked to request.branchIds
  - throws: ResourceNotFoundException if user or tenant link is not found
  - throws: InvalidOperationException if attempting to modify a Tenant Admin (role 1)

AccountManagementService.toggleAccountStatus(tenantId: UUID, targetUserId: UUID, request: LockAccountRequestDTO): void
  - pre: tenantId, targetUserId, request are not null
  - post: users.is_active updated to request.isActive
  - throws: ResourceNotFoundException if user is not found in the tenant
  - throws: InvalidOperationException if targetUserId equals current authenticated user ID (cannot lock self)
```

## Interface: `BookingSecurityService`

```text
BookingSecurityService.validateBookingOperation(booking: Booking, currentUser: UserPrincipal, opType: OperationType): void
  - pre: booking, currentUser, opType are not null
  - post: returns normally if authorized; otherwise throws AccessDeniedException
  - rules:
      - If currentUser.isSuperAdmin() -> permit all
      - If currentUser.getTenantId() != booking.getTenantId() -> throw AccessDeniedException
      - If currentUser.getRole() == 3 (SALE) and opType in (HANDOVER, RETURN) -> throw AccessDeniedException
      - If currentUser.getRole() != 1 (TENANT_ADMIN) and booking.getBranchId() not in currentUser.getBranchIds() -> throw AccessDeniedException
```

## Data Structure: `UserTenant` & `UserBranch`

```text
UserTenant {
  userId: UUID      - PK, FK to users
  tenantId: UUID    - PK, FK to tenants
  role: Integer     - 1: TENANT_ADMIN, 2: STAFF, 3: SALE
  joinedAt: Instant
}

UserBranch {
  userId: UUID      - PK, FK to user_tenants
  tenantId: UUID    - PK, FK to user_tenants
  branchId: UUID    - PK, FK to branches
  assignedAt: Instant
}
```

## Shared DTOs

```text
AccountResponseDTO {
  userId: UUID
  fullName: String
  email: String
  phone: String
  role: Integer
  isActive: Boolean
  branchIds: List<UUID>
}

RoleSwapRequestDTO {
  role: Integer       - required, range: [2, 3]
  branchIds: List<UUID> - required, non-null (empty list allowed for Sales)
}

LockAccountRequestDTO {
  isActive: Boolean   - required
}
```

# 5. Target Architecture

**Components:**
- `AccountController` - Handles REST endpoints for listing, role-swapping, and locking.
- `AccountManagementService` - Orchestrates database operations for user_tenants, users, and user_branches.
- `RoleConverter` - Maps database `SMALLINT` to Java Enum `UserRole`.
- `BookingStatusConverter` - Maps database `SMALLINT` to Java Enum `BookingStatus`.
- `BookingSecurityService` - Enforces branch scope and role restrictions for booking tasks.

**Interaction Flow (Role Swap):**

```text
Client (Postman/UI)
  -> REST: PUT /api/v1/accounts/{id}/role (RoleSwapRequestDTO)
    -> AccountController.swapRole(id, DTO)
      -> TenantSecurityContext: Validate User is Admin (role = 1)
      -> AccountManagementService.swapRoleAndBranches(tenantId, id, DTO)
        -> DB: UPDATE user_tenants SET role = :role WHERE user_id = :id
        -> DB: DELETE FROM user_branches WHERE user_id = :id
        -> DB: INSERT INTO user_branches (user_id, branch_id) VALUES (...)
  <- returns 200 OK
```

**Key Decisions:**
- **JPA AttributeConverters**: Converting roles and statuses to numbers via auto-apply converters keeps Java services type-safe (`UserRole.STAFF`) while maintaining fast integer operations in SQL.
- **Service-Level Security Enforcer**: Integrating `BookingSecurityService` into booking transitions (handover, return, create) prevents Sales agents from performing handovers regardless of their API origin.

**Description:**
Create the `RoleConverter` to map `SMALLINT` database values (1: TENANT_ADMIN, 2: STAFF, 3: SALE) to the Java Enum `UserRole`. Set up DTOs and implement the account list API scoped strictly to the current authenticated user's tenant.

**Input:**

**Output:**
- `RoleConverter`, `AccountResponseDTO`, `AccountController.listAccounts()`

**Files:**
- `backend/src/main/java/com/carrental/auth/converter/RoleConverter.java` - **create**: Map 1, 2, 3 values to Java Enum.

- `backend/src/main/java/com/carrental/auth/controller/AccountController.java` - **create**: REST controller with `GET /api/v1/accounts` restricted to role `1` (TENANT_ADMIN).

- `backend/src/main/java/com/carrental/auth/service/impl/AccountManagementServiceImpl.java` - **create**: Fetch accounts by tenant ID.

**Acceptance Criteria:**
- [ ] RoleConverter mapping: `1` -> `UserRole.TENANT_ADMIN`, `2` -> `UserRole.STAFF`, `3` -> `UserRole.SALE`.

# 9. Edge Cases

| # | Scenario | Expected Behavior | Handled In |
|---|----------|-------------------|------------|
| 1 | Admin attempts to lock themselves | Reject with 400 Bad Request, show "Cannot lock own account" error message | TASK-003 |
| 2 | Assigning a user to branches belonging to a different tenant | JPA Composite FK constraints (`fk_user_branch_user_tenant`) fail-safe reject, API throws 403 Forbidden | TASK-002 |
| 3 | Sale agent tries to call physical handover endpoint directly via API | Blocked at backend filter layer (`BookingSecurityService`), returns 403 Forbidden | TASK-004 |
| 4 | Locked user attempts to make API calls with existing active JWT token | Intercepted by authentication filter, returns 401 Unauthorized | TASK-003 |
| MT-1 | User A requests resource owned by User B (IDOR) | Return 403 Forbidden, log suspicious access attempt | TASK-002 |
| MT-2 | Request missing tenant context | Reject with 400 Bad Request, never fall back to all tenants | TASK-001 |
| MT-3 | Bulk operation with mixed-tenant items | Reject entire batch with 400 | TASK-002 |
| MT-4 | Tenant ID in URL path differs from auth token tenant | Reject with 403, log as potential ID manipulation | TASK-001 |
