## 1. Overview
The "Add New Account" feature allows a Tenant Administrator (`TENANT_ADMIN`) to create new employee accounts (either `STAFF` or `SALE` roles) within their own organization (tenant). The feature enforces strict multi-tenant boundary checks, password strength constraints, and conditional branch assignment validations.

## 2. Requirements

### 2.1 Functional Requirements
1. **Endpoint Access**: Restricted to authenticated users with the role `TENANT_ADMIN` in the current tenant context.
2. **Account Roles**: Only allowed to create accounts with the role `STAFF` (value = 2) or `SALE` (value = 3). Creation of a `TENANT_ADMIN` (value = 1) account is prohibited.
3. **Unique Email Handling**:
   - If the email already exists in the `users` table, check if the user is already associated with the current tenant.
   - If they are already in the tenant, throw a `BadRequestException` ("Account with this email already exists in your organization").
   - If they are NOT in the tenant, instead of creating a new `User` entity, switch to associating the existing user with the current tenant, set their role, and assign their branches. The password field will not be updated to prevent security breaches on other tenants.
4. **Password Hashing**: Store passwords securely by hashing them using the application's `PasswordService` (`BCryptPasswordEncoder`).
5. **Initial Status**: All newly created accounts are active (`is_active = true`) by default.

### 2.2 Input Validations & Constraints
- **Full Name**: Mandatory (`@NotBlank`).
- **Email**: Mandatory (`@NotBlank`), must be a valid email address format (`@Email`).
- **Password**: Mandatory (`@NotBlank`), must be at least 8 characters long and contain both letters and numbers (Regex: `^(?=.*[a-zA-Z])(?=.*\\d).{8,}$`).
- **Phone Number**: Mandatory (`@NotBlank`), must start with `0`, contain only digits, and have a length of 10 or 11 characters (Regex: `^0\\d{9,10}$`).
- **Role**: Mandatory (`@NotNull`), must be either `2` (`STAFF`) or `3` (`SALE`).
- **Branch Assignment**:
  - **Duplicate Branches**: If duplicates are sent (e.g., `[branchA, branchA]`), they are automatically de-duplicated before processing.
  - **STAFF validation**: If the role is `STAFF (2)`, assigning the user to **at least one** branch is mandatory.
  - **SALE validation**: If the role is `SALE (3)`, they **must not** be assigned to any branch (the list of `branchIds` must be null or empty). If branch IDs are provided for a Sale account, reject the request.
  - **Branch Ownership**: All assigned branches must belong to the active tenant.

## 3. Technical Design

### 3.1 Proposed Data Contract (`CreateAccountRequestDTO`)
```java
package com.carrental.auth.dto;

import jakarta.validation.constraints.*;
import java.util.List;
import java.util.UUID;

public class CreateAccountRequestDTO {

    @NotBlank(message = "Email must not be blank")
    @Email(message = "Invalid email format")
    private String email;

    @NotBlank(message = "Password must not be blank")
    @Pattern(
        regexp = "^(?=.*[a-zA-Z])(?=.*\\d).{8,}$",
        message = "Password must be at least 8 characters and contain both letters and numbers"
    )
    private String password;

    @NotBlank(message = "Full name must not be blank")
    private String fullName;

    @NotBlank(message = "Phone number must not be blank")
    @Pattern(
        regexp = "^0\\d{9,10}$",
        message = "Phone number must start with 0, contain only digits, and be 10 or 11 characters long"
    )
    private String phone;

    @NotNull(message = "Role must not be null")
    @Min(value = 2, message = "Role must be 2 (STAFF) or 3 (SALE)")
    @Max(value = 3, message = "Role must be 2 (STAFF) or 3 (SALE)")
    private Integer role;

    private List<UUID> branchIds;

    // Constructors, Getters, and Setters
}
```

### 3.2 Service Layer Logic (`AccountManagementService.createAccount`)
The business logic will be encapsulated inside a new `@Transactional` method in `AccountManagementService`:

```java
@Transactional
public AccountResponseDTO createAccount(UUID tenantId, CreateAccountRequestDTO request) {
    // 1. Validate Role & Branch constraints first
    UserRole role = UserRole.fromValue(request.getRole());
    List<UUID> branchIds = request.getBranchIds();
    List<UUID> distinctBranchIds = branchIds == null ? List.of() : branchIds.stream().distinct().toList();

    if (role == UserRole.STAFF) {
        if (distinctBranchIds.isEmpty()) {
            throw new BadRequestException("Staff account must be assigned to at least one branch");
        }
    } else if (role == UserRole.SALE) {
        if (!distinctBranchIds.isEmpty()) {
            throw new BadRequestException("Sale account must not be assigned to any branch");
        }
    }

    // 2. Validate branch ownership (must all belong to the active tenant)
    if (!distinctBranchIds.isEmpty()) {
        List<Branch> tenantBranches = branchRepository.findAllByTenantId(tenantId);
        Set<UUID> tenantBranchIds = tenantBranches.stream()
                .map(Branch::getId)
                .collect(Collectors.toSet());

        if (!tenantBranchIds.containsAll(distinctBranchIds)) {
            throw new TenantAccessDeniedException("One or more branches do not belong to this tenant");
        }
    }

    // 3. Check if email already exists
    Optional<User> existingUserOpt = userRepository.findByEmail(request.getEmail());
    User targetUser;

    if (existingUserOpt.isPresent()) {
        targetUser = existingUserOpt.get();
        // Check if already associated with this tenant
        boolean alreadyAssociated = userTenantRepository.findById(new UserTenant.UserTenantId(targetUser.getId(), tenantId)).isPresent();
        if (alreadyAssociated) {
            throw new BadRequestException("Account with this email already exists in your organization");
        }
    } else {
        // Create and Save new User Entity
        String encodedPassword = passwordService.encode(request.getPassword());
        targetUser = User.builder()
                .email(request.getEmail())
                .passwordHash(encodedPassword)
                .fullName(request.getFullName())
                .phone(request.getPhone())
                .isActive(true)
                .isSuperAdmin(false)
                .build();
        targetUser = userRepository.save(targetUser);
    }

    // 4. Create and Save UserTenant Relationship
    UserTenant userTenant = UserTenant.builder()
            .userId(targetUser.getId())
            .tenantId(tenantId)
            .role(role)
            .build();
    userTenantRepository.save(userTenant);

    // 5. Save UserBranch Mappings (STAFF only)
    if (role == UserRole.STAFF) {
        List<UserBranch> userBranches = distinctBranchIds.stream()
                .map(branchId -> UserBranch.builder()
                        .userId(targetUser.getId())
                        .tenantId(tenantId)
                        .branchId(branchId)
                        .build())
                .toList();
        userBranchRepository.saveAll(userBranches);
    }

    // 6. Map to AccountResponseDTO and return
    return AccountResponseDTO.builder()
            .userId(targetUser.getId())
            .fullName(targetUser.getFullName())
            .email(targetUser.getEmail())
            .phone(targetUser.getPhone())
            .role(role.getValue())
            .isActive(targetUser.isActive())
            .branchIds(distinctBranchIds)
            .build();
}
```

### 3.3 Controller Layer Endpoint (`AccountController.createAccount`)
An endpoint `POST /api/v1/accounts` will be added to the controller class:

```java
@PostMapping
public ResponseEntity<ApiResponse<AccountResponseDTO>> createAccount(
        @jakarta.validation.Valid @RequestBody CreateAccountRequestDTO request) {
    
    UUID tenantId = TenantContext.getTenantId();
    if (tenantId == null) {
        throw new BadRequestException("Tenant context is required");
    }

    AccountResponseDTO createdAccount = accountManagementService.createAccount(tenantId, request);
    return ResponseEntity.status(HttpStatus.CREATED)
            .body(ApiResponse.success(createdAccount, "Account created successfully"));
}
```

## 4. Verification Plan

### 4.1 Unit & Integration Test Scenarios
- **TC-01: Create Staff Successfully**: Verify a staff account is successfully created with correct email, encoded password, `is_active = true`, correct role mappings, and assigned branches.
- **TC-02: Create Sale Successfully**: Verify a sale account is successfully created with no branch assignment.
- **TC-03: Block Existing Email**: Attempting to create an account with a globally registered email should throw a `400 Bad Request` with message "Email is already in use".
- **TC-04: Block Invalid Password**: Attempting to create an account with a simple password (e.g. `12345678` or `abcdefgh`) should fail with validation error.
- **TC-05: Block Invalid Phone**: Attempting to create an account with a phone not matching `^0\d{9,10}$` should fail with validation error.
- **TC-06: Block Staff Without Branches**: Creating a `STAFF` account with empty/null branch list should throw a `400 Bad Request`.
- **TC-07: Block Sale With Branches**: Creating a `SALE` account with non-empty branch list should throw a `400 Bad Request`.
- **TC-08: Block Unowned Branches**: Assigning a branch that does not belong to the administrator's tenant should throw a `TenantAccessDeniedException` (or a `403 Forbidden` mapped response).
- **TC-09: Block Non-Admin Creators**: Verify that calls to `POST /api/v1/accounts` by roles other than `TENANT_ADMIN` (e.g. `STAFF` or `SALE`) are rejected by spring-security with a `403 Forbidden`.
