# Implementation Plan: Quản lý Chi nhánh (Branch Management)

## 1. Context & Non-Goals

### Context
Tính năng Quản lý Chi nhánh cho phép Chủ nhà xe (`TENANT_ADMIN`) quản lý danh sách bãi xe và địa điểm giao nhận. Hệ thống áp dụng **Mô hình Hybrid SaaS Quota** để kiểm soát số lượng chi nhánh (`max_branches`) và xe (`max_vehicles`) dựa trên Gói cước (Subscription Package), bảo vệ tài nguyên server và ngăn ngừa rác dữ liệu.

### Non-Goals
- Không xây dựng giao diện tìm kiếm chi nhánh cho khách hàng trên Public Website.
- Không tích hợp bản đồ vệ tinh / GPS live tracking vị trí bãi xe.

---

## 2. Constraints

- **Tech Stack**: Java 17, Spring Boot 3.3.x, Spring Data JPA, Flyway, PostgreSQL 15+.
- **Bảo mật Multi-tenant**: Kiểm tra Postgres RLS (`app.current_tenant`), bảo mật API theo Role (`TENANT_ADMIN` = 1 cho các tác vụ ghi, `STAFF` = 2 / `SALE` = 3 chỉ xem chi nhánh được phân công).
- **Quy trình Phát triển**: TDD là bắt buộc (Red → Green → Refactor).

---

## 3. Conventions & Logging Rules

- **Package Location**: `com.carrental.branch.*` (`entity`, `repository`, `dto`, `service`, `controller`).
- **Error Handling**: Thăng cấp ngoại lệ qua `GlobalExceptionHandler` với `ApiResponse<T>` chuẩn và mã lỗi nghiệp vụ (`BRANCH_*`).
- **Logging Rules**:
  - Log lý do khi thoát sớm (Guard Clauses / Early Returns).
  - Log thông tin ngữ cảnh trong khối `catch` trước khi ném ngoại lệ.
  - Log nhánh rẽ được thực thi trong các điều kiện logic phức tạp.

## 4. Contracts & Data Transfer Objects

### 4.1 Data Transfer Objects (DTOs)

```java
public class CreateBranchRequestDTO {
    @NotBlank(message = "Branch code must not be blank")
```

### Task 4: Implement BranchService (TDD Cycle)
- **Phase**: Phase 2
- **Files**: `BranchService.java`, `BranchServiceImpl.java`, `BranchServiceTest.java`
- **Dependencies**: Task 2, Task 3 (`[2, 3]`)
- **Parallel Group**: Group C
- **Acceptance Criteria (Red → Green → Refactor)**:
  - `createBranch`: Thất bại nếu `currentBranchCount >= max_branches` (ném `BRANCH_QUOTA_EXCEEDED`). Thất bại nếu trùng `code` trong Tenant (ném `BRANCH_CODE_EXISTS`).
  - `updateBranch`: Thất bại nếu không tìm thấy Chi nhánh (ném `BRANCH_NOT_FOUND`).
  - `changeBranchStatus`: Đổi giữa `ACTIVE` và `INACTIVE`.
  - `deleteBranch`: Thất bại nếu chi nhánh đang chứa xe (ném `BRANCH_HAS_ACTIVE_VEHICLES`). Nếu hợp lệ, đánh dấu `is_deleted = true`.
  - Logging: Log early return khi kiểm tra Quota/Code trùng/Safety delete failure.

### Task 5: Implement BranchController (TDD Cycle)
- **Phase**: Phase 3
- **Files**: `BranchController.java`, `BranchControllerIT.java`
- **Dependencies**: Task 4 (`[4]`)
- **Parallel Group**: Group D
- **Acceptance Criteria (Red → Green → Refactor)**:
  - `GET /api/v1/branches`: Trả về `200 OK` kèm danh sách phân trang (Cho phép `TENANT_ADMIN`, `STAFF`, `SALE`).
  - `GET /api/v1/branches/{id}`: Trả về `200 OK` (Cho phép `TENANT_ADMIN`, `STAFF`, `SALE`).
  - `POST /api/v1/branches`: Trả về `201 Created` (Chỉ `TENANT_ADMIN`, ném `403` với `STAFF`/`SALE`).
  - `PUT /api/v1/branches/{id}`: Trả về `200 OK` (Chỉ `TENANT_ADMIN`).
  - `PATCH /api/v1/branches/{id}/status`: Trả về `200 OK` (Chỉ `TENANT_ADMIN`).
  - `DELETE /api/v1/branches/{id}`: Trả về `200 OK` hoặc `204 No Content` (Chỉ `TENANT_ADMIN`).

## 9. Edge Cases & Handling Strategy

| Edge Case | Handled In | Handling Strategy |
| :--- | :--- | :--- |
| **Vượt Quota Chi nhánh** | Task 4 | Đếm `countByTenantIdAndIsDeletedFalse`, so sánh với `max_branches` của Tenant. Ném `BRANCH_QUOTA_EXCEEDED` (400). |
| **Mã Chi nhánh bị trùng** | Task 4 | Call `existsByTenantIdAndCodeAndIsDeletedFalse`. Ném `BRANCH_CODE_EXISTS` (400). |
| **Xóa Chi nhánh đang có Xe** | Task 4 | Call `vehicleRepository.countByBranchId`. Nếu > 0, ném `BRANCH_HAS_ACTIVE_VEHICLES` (400). |
| **Nhân viên / Sale cố tình tạo Chi nhánh** | Task 5 | Thêm `@PreAuthorize("hasRole('TENANT_ADMIN')")` ở Controller. Trả về `FORBIDDEN_ROLE` (403). |

## 10. Technical Risks & Mitigations

- **Rủi ro Postgres RLS trong Integration Test**: Trong IT Test, nếu không nạp `tenant_id` vào session, câu lệnh query sẽ bị RLS chặn.
  - *Khắc phục*: Sử dụng `JwtAuthenticationFilter` mock token chuẩn chứa `tenant_id` trong `@WithMockUser` hoặc Security Test Context.
