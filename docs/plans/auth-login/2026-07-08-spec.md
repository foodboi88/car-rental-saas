# Design Specification: Backend Project Base & Role-Based Login

## 1. Context & Objectives

This document specifies the technical design for initializing the backend base of the Car Rental SaaS system and implementing the core authentication and authorization flow. 

The primary objectives are:
- Initialize a clean, robust Spring Boot 3.3.x codebase with Java 17, Spring Security, Spring Data JPA, Flyway, and PostgreSQL.
- Establish a secure multi-tenant identity and access control layer using JWTs (Access + Refresh tokens).
- Implement a role-based authority hierarchy (`SUPER_ADMIN`, `TENANT_ADMIN`, `BRANCH_MANAGER`, `STAFF`).
- Provide a robust mechanism for users with multiple tenant memberships to select their working tenant context during login.

## 3. Database Schema

The database schemas will be managed via Flyway. 

### V1__init_schema.sql
Creates the foundational tables for tenant isolation and authentication.

```sql
CREATE TABLE tenants (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    domain VARCHAR(255) UNIQUE NOT NULL,
    plan_tier VARCHAR(20) NOT NULL DEFAULT 'FREE' CHECK (plan_tier IN ('FREE', 'BASIC', 'PRO', 'ENTERPRISE')),
    logo_url VARCHAR(500),
    contact_email VARCHAR(255),
    contact_phone VARCHAR(20),
    settings JSONB DEFAULT '{}',
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    full_name VARCHAR(255),
    phone VARCHAR(20),
    avatar_url VARCHAR(500),
    is_active BOOLEAN DEFAULT TRUE,
    is_super_admin BOOLEAN DEFAULT FALSE,
    last_login_at TIMESTAMP WITH TIME ZONE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_tenants (
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    role VARCHAR(20) NOT NULL CHECK (role IN ('TENANT_ADMIN', 'BRANCH_MANAGER', 'STAFF')),
    joined_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, tenant_id)
);

CREATE TABLE branches (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    address TEXT,
    phone VARCHAR(20),
    email VARCHAR(255),
    is_central BOOLEAN DEFAULT FALSE,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT unique_branch_tenant UNIQUE (id, tenant_id)
);

CREATE TABLE user_branches (
    user_id UUID NOT NULL,
    tenant_id UUID NOT NULL,
    branch_id UUID NOT NULL REFERENCES branches(id) ON DELETE CASCADE,
    assigned_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (user_id, branch_id),
    FOREIGN KEY (user_id, tenant_id) REFERENCES user_tenants(user_id, tenant_id) ON DELETE CASCADE
);

-- Indexing for lookup performance
CREATE INDEX idx_tenants_domain ON tenants(domain);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_user_tenants_tenant_id ON user_tenants(tenant_id);
CREATE INDEX idx_branches_tenant_id ON branches(tenant_id);
CREATE INDEX idx_user_branches_branch_id ON user_branches(branch_id);
CREATE INDEX idx_user_branches_tenant_id ON user_branches(tenant_id);
```

## 4. Multi-Tenant Login & Selection Flow

### Login Request
```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "Password123!"
}
```

### Auth Flow Logic in AuthService:
1. Load User by email. If not found, throw `BadCredentialsException` (standardized message).
2. Validate password via BCrypt. If incorrect, throw `BadCredentialsException`.
3. Check if user is active. If inactive, throw `DisabledException`.
4. If `is_super_admin == true`:
   - Issue Access JWT with claims: `tenant_id = null`, `branch_ids = null`, `role = SUPER_ADMIN`.
   - Issue Refresh Token.
   - Return `LoginResponse` containing user info, token, and `requiresTenantSelection = false`.
5. If `is_super_admin == false`:
   - Query `user_tenants` for all active memberships.
   - **Case 0 tenants**: Throw `AccessDeniedException` (User is registered but not onboarded to any tenant).
   - **Case 1 tenant**:
     - Automatically select this tenant.
     - Lookup role in `user_tenants`.
     - Lookup assigned branches in `user_branches` for this tenant.
     - Issue Access JWT with claims: `tenant_id = tenantId`, `role = role`, `branch_ids = [branchId1, ...]`.
     - Issue Refresh Token.
     - Return `LoginResponse` with token, user info, selected tenant info, and `requiresTenantSelection = false`.
   - **Case 2+ tenants**:
     - Collect list of `TenantOption` (tenantId, tenantName, role).
     - Return `LoginResponse` with `requiresTenantSelection = true`, list of `tenants`, and no JWT access token yet. (Can issue a short-lived "pre-auth-token" or transient session to secure the select-tenant step).

### Tenant Selection Request (Only if multiple tenants)
```http
POST /api/v1/auth/select-tenant
Content-Type: application/json
Authorization: Bearer <pre-auth-token-or-temporary-jwt>

{
  "tenantId": "tenant-uuid-1"
}
```
**Logic**:
1. Retrieve authenticated user identity from context.
2. Validate user belongs to the requested `tenantId` in `user_tenants`.
3. Fetch role and branch assignments.
4. Issue final Access JWT and Refresh Token.

## 5. Token Management

### Access Token (JWT)
- **Expiration**: 15 minutes.
- **Payload Structure**:
  ```json
  {
    "sub": "user-uuid",
    "email": "user@example.com",
    "role": "SUPER_ADMIN | TENANT_ADMIN | BRANCH_MANAGER | STAFF",
    "tenant_id": "tenant-uuid-or-null",
    "branch_ids": ["branch-uuid-1", "branch-uuid-2"]
  }
  ```
- **Storage**: Response body (in-memory on front-end).

### Refresh Token (JWT)
- **Expiration**: 7 days.
- **Payload Structure**:
  ```json
  {
    "sub": "user-uuid",
    "jti": "random-uuid-token-id",
    "type": "refresh"
  }
  ```
- **Storage**: Returned in HTTP-only, Secure, SameSite=Strict cookie named `refresh_token` targeting route `/api/v1/auth/refresh`.

### Token Revocation
- Store revoked Refresh Token JTI identifiers in a database table or Redis (in-memory lookup map for MVP).
- On logout, or when a user's password changes, invalidate existing refresh tokens.

## 6. Security & Tenant Context Configuration

### Spring Security
- Stateless session management.
- JWT Filter placed before `UsernamePasswordAuthenticationFilter`.
- Permit all requests to `/api/v1/auth/login` and `/api/v1/auth/refresh`.
- Standardize CORS configuration to allow trusted origins.

### TenantContext
- Global thread-local context storage:
  ```java
  public class TenantContext {
      private static final ThreadLocal<UUID> CURRENT_TENANT = new ThreadLocal<>();
      private static final ThreadLocal<List<UUID>> CURRENT_BRANCHES = new ThreadLocal<>();

      public static void setTenantId(UUID tenantId) { CURRENT_TENANT.set(tenantId); }
      public static UUID getTenantId() { return CURRENT_TENANT.get(); }
      public static void setBranchIds(List<UUID> branchIds) { CURRENT_BRANCHES.set(branchIds); }
      public static List<UUID> getBranchIds() { return CURRENT_BRANCHES.get(); }
      public static void clear() {
          CURRENT_TENANT.remove();
          CURRENT_BRANCHES.remove();
      }
  }
  ```
- `JwtAuthenticationFilter` resolves claims, sets variables in `TenantContext`, and clears them in a `finally` block at request completion.
